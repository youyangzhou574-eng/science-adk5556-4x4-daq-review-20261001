# 二、复位方案我现在直接改方向：不用继续折腾 G17→G07 主方案

R2.1 提出的：

`外部RESET → 4.99k → Schmitt → G07开漏 → PGOOD/NRST`

理论上能工作，但它又引入了一个 **Schmitt门限全供电范围资料不完整** 的新HOLD。

这个工程上没有必要。

## 采用更简单的 RST-A

首版复位接口改为：

**J3.5外部NRST → 1.00 kΩ串阻 → PGOOD/MCU_NRST**

板内保留：

- 10 kΩ到3.3 V的上拉；
- MCU自身NRST内部上拉；
- 现有上下轨BAT54S钳位；
- TPS3890的开漏RESET也直接作用于这个节点。

外部接口契约定义成：

**active-low open-drain/open-collector，释放时Hi-Z；保证拉低时 \(V_{OL}\le0.4\) V。**

这就是SWD调试器正常的复位接口类型，不需要把它当任意5 V数字输入。

按保守角点先算一遍：

- 板上10 kΩ取强上拉端；
- MCU内部上拉取25 kΩ；
- 1 kΩ串阻取+1%；
- VDD取3.6 V；
- 外部低电平取0.4 V；

得到 NRST 大约：

\[
V_\mathrm{NRST}\approx0.797\text{ V}
\]

而最低供电3.065 V下，MCU保证低阈值：

\[
0.3V_{DD}=0.9195\text{ V}
\]

仍有约 **0.12 V** 门限裕量。

而且在这个角点下，额外向NRST注入的总泄漏要达到约 **139 µA** 才会把节点推到0.9195 V；正常逻辑/钳位泄漏应远小于这个量级，下一包用原厂保证值正式闭合即可。

### 因此正式裁定

**G17→G07复位候选退出主线。**

原：

`RESET_THRESHOLD_ENVELOPE_HOLD`

作为**被放弃候选的历史HOLD关闭，不再阻塞项目**。

新活动门改为：

`RESET_DIRECT_PATH_VERIFICATION_PENDING`

下一包只需核：

1. MCU NRST上下阈值；
2. 内部上拉；
3. BAT54S漏电；
4. 调试器接口VOL契约；
5. ±故障电流；
6. TPS3890开漏并联状态。

如果这六项通过，就可以直接画进去。

这样比多加两个逻辑芯片更简单，也更适合首版。

# 三、≤10 ms故障判定也不用和10 ms整帧周期硬碰硬

目前最大的逻辑矛盾是：

正常完整帧可能允许到 **10.25 ms**，那么只靠“完整帧多久没来”无法同时保证 **≤10 ms故障失效**。

解决方法不是把100 fps改掉，而是使用**帧内进度看门狗**。

## 下一版协议固定增加 `acquisition_progress`

现有约1 ms heartbeat中加入：

- `epoch`
- 当前 `frame_id`
- 当前完成的 `state_index`（0–7）
- 该状态最后一个有效采样完成时间
- 可选当前累计有效sample数量

**不需要增加一个新的高速数据包流，复用现有heartbeat即可。**

八状态每个状态约1.2 ms。因此：

### 安全状态契约

- heartbeat完全消失：**4.5 ms**超时；
- heartbeat还在，但 `acquisition_progress` **2.5 ms没有前进**：立即清 `DATA_VALID`；
- PGOOD低：立即硬件禁激励，同时软件数据失效；
- ADC标签/范围/样本错误：当状态内发现时立即失效；
- 10.25 ms frame-age只保留为普通“旧数据”保护，**不再负责≤10 ms安全故障时延证明**。

这样即使ADC采集线程卡死、但主循环还在发heartbeat，也不会等完整10.25 ms才发现。

正式目标：

\[
t_{\text{progress timeout}}=2.5\text{ ms}
\]

即使再给传输/接收调度留余量，设计级故障失效依然明显小于10 ms。

这部分先关闭**逻辑契约**，真实MCU/WCET/UART/SPI硬件时延以后bench验证。

# 四、耦合模型：不再要求死磕“10个宏模型跑完整9.6 ms”这一条路

这是下一包最关键的改变。

完整宏模型跑不动，不等于必须一直等到它跑完才能做工程。

下一轮改成**分层耦合验证**。

## Tier 1：先验证返回比方法本身

现在使用：

\[
L=-V(fb)/V(minus)
\]

的高阻串联电压注入方法。

需要针对每类环路至少做一次**第二种独立验证方法**：

- Middlebrook/Tian等保持负载的方法；
- 或独立闭环极点/阶跃验证。

方法通过门：

- 主交越频率差 ≤10%；
- PM差 ≤5°；
- 所有交越必须被两种方法解释；
- 不允许出现“一个方法单交越，另一个多交越”而仍标PASS。

如果这个门不过，就先修验证方法，不修电路。

## Tier 2：完整10运放模型先做静态状态 AC / PZ，而不是9.6 ms transient

分别建立固定状态：

- all blank；
- ROW0 active；
- ROW1 active（对称检查）；

阻值至少：

- 全800 Ω；
- 全8000 Ω；
- 高目标+低邻居。

在**不进行外部MUX时序切换**的条件下，先跑：

- operating point；
- 完整耦合AC；
- 能执行时加 `.pz`。

目标是回答：

**闭环静态系统有没有右半平面极点或明显危险的耦合模态。**

这比让10个宏模型从0一直积分到9.6 ms更直接。

`.pz`若因宏模型结构不支持，可以失败并保留，不要求强行改模型。

## Tier 3：逐步增加实际宏模型数量

固定同一外部状态，依次运行：

1. VCM/VEXC + 1行 + 1TIA；
2. VCM/VEXC + 4行 + 1TIA；
3. VCM/VEXC + 1行 + 4TIA；
4. 最后才尝试完整4行+4TIA。

每个正常暂态只需要覆盖：

**切换前50–100 µs + 切换后400–500 µs**

而不是每次跑完整9.6 ms。

我们真正需要验证的是 **300 µs后能否进入有效窗口**，不是证明仿真器可以把整帧完整积分一遍。

## Tier 4：数值诊断允许Gear，但不能拿Gear“证明稳定”

当前 OPA4388 模型里本身有多组 `VSWITCH`、LIMIT和ESD非线性。多个宏模型并联后出现小时间步长完全可能是模型刚性。

允许做：

- trapezoidal；
- Gear；
- KLU/default solver；

的有限对照。

但是：

**Gear仅作为“数值收敛诊断”。**

只有当：

- reduced/partitioned模型；
- AC/返回比；
- 关键状态暂态；

互相一致时，才能把 monolithic full transient 的失败分类成模型计算限制。

不能因为Gear能跑就直接判物理稳定。

# R2.1 最小复位候选与八状态契约

这是原生写入前的候选设计，尚未修改冻结 R2 工程。

## 外部复位候选

优先 MR 方案已核对 TPS3890 数据表：MR 保证低/高为 0.25/0.7 VDD，MR 低时内部有额外电流，但电气表没有独立 MR 最大输入电流限值。不能把 MR=VDD 条件下的 IDD 最大值当 MR 拉低电流限值。本轮采用裁定允许的等效方案：独立受保护请求经 Schmitt 接收及板内开漏缓冲直接拉低 NRST/PGOOD。

连接候选：J3.5 → 既有 R_J3_5 4.99k ±1% → EXT_RESET_IN；新 47k ±1% 上拉到 V3V3；EXT_RESET_IN → SN74LVC1G17 输入；其输出 → SN74LVC1G07 输入；SN74LVC1G07 开漏输出 → PGOOD/MCU NRST。两个逻辑器件使用 V3V3/GND、各 100nF 去耦。新 G17 复用既有核心库身份；G07 为一个候选新身份，未搜索/导入原生库。

J3.5 的原 BAT54S 轨钳位撤出此独立输入：逻辑输入本身支持 0–5.5V，掉电 Ioff 有限值，避免未知高温 BAT 漏电进入低电平分压；其他接口保护不变。负故障仍由串阻限制输入内部负钳位电流，只能接受限值分析，不能据绝对最大值宣布连续负故障运行安全。

正常外部低电平契约 VEXT≤0.2V，V3V3=3.065–3.6V。4.99k/47k 与输入 ±5µA 取最坏组合，输入低最大约0.555V，高最小约2.828V。G17 表中 2.3/3/4.5V 离散测试点对应 VT− 最小0.56/0.89/1.51V，VT+ 最大1.56/1.92/2.74V；候选有低/高裕量，但表没有明确给出整个3.065–3.6V区间的门限包络，不能把离散点单调性推断写成厂家全区间保证。此项保留 **RESET_THRESHOLD_ENVELOPE_HOLD**，作为集中缺口回传。

G17 → G07：G17 小负荷 VOL≤0.1V、VOH≥VCC−0.1V，G07 在3–3.6V要求 VIL≤0.8V、VIH≥2V。PGOOD 总下拉负荷计10k上拉、MCU NRST最小25k内部上拉及输入漏电，保守≤0.55mA；G07在3V/16mA给VOL≤0.4V，因此远低于NRST的0.3VDD（最低0.9195V），并低于既有G17在3V的VT−下限。原1.099V分压路径已从架构上消除，但原生实现未进行。

输出释放按两TPS3890各250nA、G07输出漏电采用10µA保守工程分配、G17输入5µA、MCU总漏电15µA工程分配计算，10k最坏下压≤0.31V，NRST仍高于0.7VDD。MCU总漏电分配须结合整板引脚条件验证，不能称实物保证。

外部请求撤销不会经过TPS3890 CT延时，本候选靠复位epoch、100ms重新等待、配置读回、两个连续完整帧恢复资格；原电源监督的CT=100nF仍有约107ms名义释放延时。需要MR硬件延时的方案应在后续集中裁定中明确选择，不能把本方案说成已执行MR方案。

掉电正请求+5.5V：输入容忍与Ioff限值可用，47k上拉形成有限回灌；含100Ω吸收的候选rail边界在 RESET_CORNERS.json。负请求−5.5V的输入钳位电流≤1.12mA，仅限绝对最大电流比较；60s热行为/部分供电行为仍HOLD。

## 八状态与实际计算

BLANK0→ROW0→BLANK1→ROW1→BLANK2→ROW2→BLANK3→ROW3。每状态300µs建立等待、四通道各9×25µs，合计1200µs。每帧9600µs、288传输、32dummy、256有效样本。每行每列实际执行D=mean(8 active codes)−mean(8 adjacent blank codes)，同一固定校准系数另取冻结R2校准输入，绝不逐帧重新校准。

48 clocks @4MHz =12µs。采用 **SPI mode1、在falling edge捕获前一个已稳定SDO位**，16th falling edge推出B15，在17th falling edge采入B15；因此接收48bit为16前导位+16数据+4通道+2器件+3量程+7尾位。依据ADS8684原厂Table13/14及TI接口说明，三个字面位串独立于编码器构造。数字电平/硬件采样保持尚未验证；这修订了旧报告中笼统的rising-edge capture假设。

400µs额外开销分配：八次GPIO切换32µs；16单元差分和固定校准120µs；帧整理与发送70µs；资格处理32µs；时钟调度余量100µs，共354µs，余46µs。288次DMA服务每次≤0.5µs必须放在已有25µs周期的13µs空档中，不再重复挤占400µs。上述是未实测的固件预算，不是已有固件WCET。

## 接收与失效

uint32帧号严格连续、0xffffffff→0回绕；每次复位单调增大epoch；采集完成与接收时间分开。采集周期9.75–10.25ms，传输≤0.5ms；拒绝旧epoch、旧采集、缺样、跳号、错标签；异常清除连续计数。无需新数据的tick入口检查心跳4.5ms超时及采集年龄10.25ms。心跳约1ms，携带epoch和最后完整帧号。恢复需要两个完整连续帧。

≤10ms实体故障失效不能由10.25ms数据新鲜度阈值证明。预算候选为板端检测4ms、发送1ms、接收端最坏超时4.5ms+调度0.25ms，合计9.75ms；代码采用4.5ms心跳超时与此一致。这些是设计分配，板端检测与实际调度均未实测，仍为 **FAULT_LATENCY_CONTRACT_HOLD**。持续心跳而不更新完整帧的缺帧失效由10.25ms数据年龄阈值处理，不能冒称这一路径也≤10ms；需更高频帧内进度/诊断契约或另行判定允许的帧截止规则。

最终软件审查修订：异常/超时仅清连续资格，不清同epoch的已接收帧号及采集时间水位；新帧必须在uint32半区间内向前且采集时间递增。接收器有限单调时钟跨clear及新epoch保留。旧帧不得作为恢复首帧，两帧恢复必须为两帧新的完整连续帧。21项实际回归通过，见FINAL_REVIEW.md。
